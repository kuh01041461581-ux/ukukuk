# 익산타이쿤 도트 제작 규칙

건물 도트는 **원본과 똑같은 방식(게임의 조각 규칙)** 으로 만든다. 한 장짜리 그림을 그대로 넣으면 게임 안에서 조각이 흩어져 깨진다.

## 1. 게임이 건물을 그리는 법

건물 시트(`data1.pak` 의 `b#.d`, 폭 96)는 한 장으로 그려지지 않는다. `yx.d` 의 조각표대로 잘라, 조각마다 정해진 자리에 붙인다. **건물마다 조립 방식이 다르다.**

`yx.d` 구조 (`tools/yx_table.py` 가 읽는다):

| 위치 | 내용 |
|---|---|
| 132 ~ 1331 | 조각 사각형 300개 `(x, y, w, h)`. 건물 순서대로 이어진다. 건물의 0번 조각이 메인(가로 96). |
| 1332 ~ 끝 | 건물 65개 기록. 프레임마다 `(조각번호, 화면 x, 화면 y)` 목록. 마지막 프레임이 덧조각까지 포함한 전체 모습. |

- 화면 좌표는 조립 그림의 좌표다(폭 96, 위가 0). 메인은 `(0, MY)` 에 놓인다.
- 시트 높이는 항상 `H = 메인 y + 메인 높이 + 8`. 마지막 8줄은 바닥 끝 조각이고 표에 없다:
  시트 `(0, H-8, 64, 8)` → 화면 `(16, MY+mh)`, 시트 `(64, H-8, 32, 8)` → 화면 `(32, MY+mh+8)`.
- 바닥 마름모는 2:1. 가장 넓은 줄은 `MY + mh - 8`, 아래 끝은 `MY + mh + 16`.
- 프레임이 여러 개인 건물은 조각을 바꿔 가며 그린다(깜빡이는 불빛, 차 등).
- 조각의 화면 위치는 고정이다. `yx.d` 에서 바꿀 수 있는 것은 조각의 시트 위치와 폭뿐이다.
- b59~b64(뉴타운 특수 건물)는 표 순서가 달라 아직 맞추지 못했다.

## 2. 만드는 순서

1. `strips.canvas(k)` 로 캔버스 높이와 마름모 줄을 얻어 `Sc.OVR` 에 넣고 완성 그림을 그린다(폭 96).
2. `strips.to_sheet(k, F)` 로 조각 칸에 나눠 담는다. 조각은 오른쪽으로 넓히고, 시트에서 겹치거나 여러 자리에 찍히는 덧조각은 끈다(1x1).
3. `strips.patch_yx()` 로 `mod/yx.d` 를 고친다.
4. `strips.compose(k, 시트, 조각)` 으로 게임이 조립한 모습을 확인한다. 원본 시트도 같은 함수로 조립해 볼 수 있다.
5. 건설 목록에 나오는 건물은 실제 게임 화면에서 확인한다.

이 과정은 `tools/build_sprites.py` 가 한 번에 한다. **빌드 스크립트는 이것만 부른다.** 생성기를 따로 돌려 `work/pak_mod` 에 직접 쓰지 않는다(빌드 때 지워지고 다시 만들어진다).

새 건물을 추가할 때는 `build_sprites.py` 의 `ITEMS` 에 `건물 번호: 그리는 함수` 를 넣는다.

## 3. 주의

- 조립 그림에서 어느 조각에도 덮이지 않는 자리는 게임에 보이지 않는다. 위로 갈수록 조각이 좁아지는 건물은 윗부분을 그 폭 안에 그린다.
- 원본보다 훨씬 큰 건물은 이웃 지형에 가려질 수 있다.

## 4. 지형 조각 (`d#.d`, 64x64)

- 지형은 조각 규칙이 없다. 원본 조각 위에 덧칠한다.
- 도로·울타리·집을 지우지 않는다. 바꿀 화소만 색으로 골라 칠한다.
- 이웃 조각과 이음새가 맞도록 원본의 명암을 그대로 살린다.

## 5. 원본에 글자·색만 고칠 때

- 한 조각에만 속한 자리를 고친다. 조각이 겹치는 자리에 그리면 같은 그림이 두 번 찍힌다.
- 마지막 8줄(바닥 끝 조각)에는 건물 그림을 넣지 않는다.

## 6. 확인 방법

- `python3 -I tools/build_sprites.py 전시.png` : 변환한 건물 전체를 게임 조립 방식으로 본다.
- 하니스(`st2android/test/JvmRun.java`, `REPL` 모드)로 튜토리얼을 자동으로 넘긴 뒤 건설 목록을 열어 실제 화면을 찍는다.
- 원작 그림이 들어간 미리보기는 저장소에 올리지 않는다.
