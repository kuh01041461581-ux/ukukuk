# 익산타이쿤 시스템 변경 검토 (2026-11)

게임(서울타이쿤2)의 로직은 ARM 기계어로 컴파일돼 있어서, 바꿀 수 있는 층위가 나뉜다.

## 1. 바로 바꿀 수 있는 것 (텍스트·그림, 검증 완료)
| 항목 | 상태 | 비고 |
|---|---|---|
| 지명·건물명·비서명·대사 | 대부분 완료 | `st2android/mod/text_map.json`. 255바이트 제한, 이미지 속 이름은 같은 글자 수만 가능 |
| 행사(축제) 문구 | 완료 | 서동축제(5월), 천만송이 국화축제(가을), 보물찾기 보석축제를 반영 |
| 정책·이벤트·뉴스 문구 | 일부 | 정책 이름/선택지(l17, l19), 재해(l13 27~30), 임기 후 뉴스(m1) 를 익산 현안으로 바꿀 수 있음 |
| 건물·지형·로고 그림 | 진행 중 | 건물 그림 65개 중 시청급 31개 교체 (docs/catalog_*.png 참고) |
| 화질 | 완료 | EPX 4배 확대 + 보간 (PC·안드로이드) |
| PC 입력 | 일부 | 번호 선택지 클릭, 끌어서 지도 이동, 패드식 키보드. 필지 클릭은 미구현 |

## 2. 구조를 읽어 보니 가능성이 있는 것
- **뉴타운 3종**(글로벌/테마파크/환경): 각 4개 건물이 기존 건물의 업그레이드. 게임 설정이라 유지.
- **임기 4년**: 날짜 배열의 연도가 1~4. 임기 끝 뉴스(m1 19~31)에 `재선(21번)`·대통령 당선·베이징 시장·여행사 사장·구속·사망·자격박탈 등 결과가 이미 있음 → 재선이 이미 하나의 결말. "연임 계속" 시스템은 재선 결말에서 날짜를 1년차로 되돌려 이어 가는 방식으로 얹을 수 있으나, **임기 끝 흐름을 아직 실제로 돌려 보지 못함** (튜토리얼 중 시간이 멈춰 있어 튜토리얼을 끝내야 실험 가능).
- **상태 배열**: `int[12]` = {년, 월, 일, 예산?(200), 자재?(10), 인력?(10), …, 지지도(50), …, 남은 일수(1459)}. 읽기는 된다(날짜 표시에 이미 사용).

## 3. 해 봤는데 안 된 것 (이번 실험)
- 힙에서 찾은 상태 배열에 값을 써 보았다(예산 777, 자재 55, 인력 66, 지지도 83, 날짜 유지). **화면의 예산·자재·인력 숫자는 바뀌지 않았다.** 찾은 배열이 게임이 실제로 쓰는 객체가 아니거나(행동마다 복사본이 생김), 숫자가 다른 필드에서 그려지는 것으로 보인다. → 상태를 바꾸는 시스템(보너스·연임)은 "실제 사용 객체 찾기"가 선행돼야 한다.
- `nx.d`/`lx.d`/`mx.d` 는 스프라이트 오프셋·배치 표에 가깝고, 건설비·수입 같은 밸런스 수치로는 읽히지 않았다(정체 미확인).

## 4. 제안 (우선순위)
1. (바로) 정책·재해·임기 후 뉴스 문구를 익산 현안으로 전환 — 텍스트만으로 가능, 위험 낮음.
2. (바로) PC: 튜토리얼 키 자동 진행 옵션, 자동 저장 확인, 타이틀 메뉴 클릭.
3. (조사 후) 튜토리얼을 끝내고 임기 끝까지 돌려 종료 흐름 확인 → 재선 시 연임 계속 가능 여부 판단.
4. (조사 후) 실제 사용 상태 객체 찾기 → 실제 달력 행사 보너스, 간단한 HUD.
5. (보류) 건설비·수입 밸런스 — 데이터 구조 해독이 선행돼야 함.
