# 익산타이쿤 기획 초안 (v0.1)

> 상태: **조사 초안**. 지리·행정구역은 검색 결과(아래 출처)와 일반 지식으로 정리했고, 위치 관계·읍면동 수는 **익산시청 공식 행정구역도로 검증 필요**. 이 환경에서는 위키/통계 사이트 접속이 막혀 표·지도를 직접 읽지 못했다.

## 1. 확인된 사실 (출처 있음)
- 인구 약 26.7만 명(2026-06 행안부 주민등록 기준), 행정구역 51개. 인구 상위: 영등동 31,262 · 부송동 29,901 · 모현동1가 26,888 · 어양동 21,441 · 마동 18,425. (k-calc.com 요약)
- 지형: 북쪽 **미륵산**, 남쪽 김제 **모악산** 사이의 평야 분지, 동쪽은 노령산맥, 가운데로 **만경강**이 흐름. 유적 대부분이 만경강 수계. (전북일보 칼럼 요약)
- **금마면·왕궁면**에 백제 유산 밀집: 미륵사지(금마, 세계유산), 왕궁리 유적(왕궁). 왕궁면에는 보석 테마 관광지.
- 호남선·전라선 교차, 장항선 종착, **KTX/SRT 익산역**. 전북 제2의 도시.
- 산업: 익산국가산업단지(1970 지정, 노후 단지 재생 사업), 제3일반산업단지 확장(삼기면·낭산면 일대, 2025 승인).
- 함열읍: 고추장(장류) 체험관 등 식품 관련.

## 2. 권역 나누기 (제안)
서울타이쿤은 **4~5개 권역(강북/강남/강동/강서 등) × 구역(블록)** 구조. 익산도 같은 틀로 가능하다. 피처폰 제약(176×208, 메모리)이 없으므로 **5개 권역 + 권역당 3~5개 구역(총 15~20개 부지 묶음)** 으로 세분화하는 것을 권장.

| 권역(안) | 포함(안) | 성격/특색 | 게임 테마 |
|---|---|---|---|
| ① 원도심 | 중앙동·평화동·인화동·마동·남중동·동산동·창인동·송학동 | 익산역, 원도심 상권, 철도 교통 요충 | 교통·상업·역세권 재개발 |
| ② 신도심·주거 | 영등동·부송동·모현동·어양동·신동·삼성동 | 대단지 아파트, 인구 최다, 대학가(원광대 주변) | 주거·교육·복지 |
| ③ 백제문화 | 금마면·왕궁면·낭산면(북부, 미륵산 일대) | 미륵사지·왕궁리 유적·서동공원·보석박물관 | 관광·문화재·축제(서동축제) |
| ④ 산업·식품 | 삼기면·함열읍·황등읍·용동면·왕궁(식품클러스터) 일대 | 국가/일반 산단, 식품, 석재(황등) | 산업·일자리·물류 |
| ⑤ 농업·강변 | 웅포·망성·성당·용안·함라·여산·춘포·오산면 | 평야·금강/만경강 하천, 한옥마을, 농산물 | 농업·환경·재해(홍수) |

- 구역 세분화 예: ①을 [역세권 / 중앙시장 / 동산·마동 / 송학·창인] 4구역으로. 읍면동 경계는 *참고*일 뿐, 게임 구역은 **체감 생활권 + 랜드마크 중심**으로 새로 정의해도 됨.
- 서울판 매핑: 강북→원도심(번화·밀집), 강남→신도심(고급 주거·학군), 강동/서→ 외곽(개발 여지 큼). 익산판은 **백제문화 권역**이 서울에 없는 고유 축(관광·문화재 정책).

## 3. 게임 시스템 (서울판 구조 재사용)
- 지표: 인구·예산·자재·인력·**지지도**·피로, 임기 4년(월 단위 진행, 월말 정산). 서울타이쿤의 정책/사건/뉴스 구조를 그대로 재해석.
- 익산 고유 이벤트(안): 서동축제, 보석(귀금속) 산업 부침, KTX 개통 효과, 만경강 홍수, 황등 석재 수요, 노후 산단 재생, 미륵사지 세계유산 등재 후 관광객 증가.
- 데이터 구조는 서울판 해독 결과(`seoultycoon/docs`, `assets/st2_text`)를 **형식만** 참고하고 내용은 전부 새로 작성.

## 4. 그래픽 방식: 도트 vs 벡터
**결론: 도트(픽셀 아트) 권장.**
- 서울타이쿤의 정체성이 아이소메트릭 도트 → 팬 기대·톤 일치.
- 해상도 독립: 정수 배율 확대로 스마트폰/PC 모두 선명. 벡터는 도트풍 UI와 섞이면 이질적.
- **직접 제작 가능성**: 내가(AI) 생성하기엔 도트가 유리 — 팔레트·타일 규격을 정해 **코드(Python/PIL)로 아이소 타일·건물을 절차적으로 생성**하고, 변형(색 교체·층수·창문 패턴)으로 수백 종 확장 가능. 벡터(SVG)는 만들긴 쉽지만 도트풍 일관성을 맞추기 어렵다.
- 규격(제안): 타일 64×32 아이소(다이아몬드), 건물 64~64×96, 팔레트 32색 고정, 글꼴 Galmuri11(도트, OFL), 정수 배율 2~4×.
- 에셋 추출 대신 **새로 그리므로 저작권 문제 없음**(원작 그래픽 미사용). 원작 스프라이트는 규격 참고용으로만.

## 5. 기술 스택 제안
- Unity는 필수 아님. 이 환경에는 Unity 가 없어 **빌드·검증 불가** → **HTML5 Canvas(TypeScript/JS) 게임 + PWA**, 안드로이드는 이미 구축한 APK 파이프라인(aapt/dx/apksigner)으로 **WebView 래퍼 APK** 를 만들어 배포. PC 는 브라우저로 바로 실행, 스마트폰은 APK/홈화면 추가. 터치·키보드·패드 입력은 기존 `GameView` 아이디어 재사용.
- 나중에 Unity 로 옮길 수 있게 **데이터(JSON: 구역·건물·정책·사건)와 렌더링을 분리**.
